# 代码动画爆款视频制作

## 技术栈（已验证可用）
- Python + PIL 逐帧绘制，numpy 合成音效，ffmpeg 通过 stdin 管道编码。无需 Manim/LaTeX，容器里开箱即用。
- 参考实现：`engine/sort_race.py`（排序对决）。新题材复制它改：数据轨迹函数 + 布局 + 文案。
- 字体：中文 `/usr/share/fonts/truetype/wqy/wqy-zenhei.ttc`；代码 `DejaVuSansMono.ttf`。中文字符绝不能用等宽字体画（会变方框）。
- 所有尺寸乘缩放系数 `s = W / 基准宽`，一套代码同时出 1080x1920 和 1920x1080；竖屏上下堆叠，横屏左右并排。

## 硬性规则：流畅、整条、无卡顿（2026-10-18 用户反馈后定）
### 1. 整条连续渲染
- 一个渲染进程加一个编码器进程，从第 0 帧按顺序渲到最后一帧，直接写成一条 MP4。不分段渲染，不事后拼接。要提速就优化单进程，不并行切段。（两个画幅各跑一个进程可以，那是两条独立成片。）
- 每一帧只由 t = 帧号 / fps 决定，不依赖上一帧的状态。
### 2. 运动必须连续
- 不按节拍“跳格”移动。交换、滚动数字、增长、打印行都要连续运动；数据离散变化时在两个状态之间插值（例：柱子交换时在本操作时长内平滑滑到对方位置）。
- 节拍只用亮度、光晕、轻微缩放强调，每次至少 4 帧缓入缓出。
- 文字缩放/弹出必须亚像素：整字号渲染一次缓存，再用仿射变换做浮点缩放（`text_pop`）。直接改字号会因取整产生一顿一顿的抖动。
- 进度条等慢速增长元素，末端像素按小数部分混色，否则每隔一帧才动一下。
- 静止的停留画面也要保持微动（缓慢推近 2% 到 3%），避免看起来像卡住。
### 3. 转场不硬切
- 不允许单帧画面突变。场景或文字切换至少 0.8 秒，曲线用 ease-in-out（smoothstep）。
- 同一位置的文字互换用“先淡出、再淡入”（dip），不要两段文字重叠叠化。面板入场用上滑 + 透明度淡入。
- 压暗、闪白、爆点用 0.3 到 0.6 秒爬升，不要 1 帧跳亮。结尾 0.5 秒淡出到黑，音频同步淡出。
### 4. 编码
- 60fps 恒定帧率（`-fps_mode cfr`），GOP 2 秒（`-g 120`），`libx264 -crf 16 -maxrate 20M -bufsize 40M -pix_fmt yuv420p -movflags +faststart`，音频 AAC 160k。
### 5. 出片前自检（必须通过）
- 运行 `python3 scripts/qc.py 成片.mp4`：核对帧数等于时长乘 fps、时间戳连续；逐帧差分找超过局部中位数 5 倍的突变（硬切）和重复帧。硬切必须为零，重复帧只允许刻意定格。
- 再抽 5 到 7 帧拼联系表，看画面、字幕、方框字、遮挡和配色。

## 爆款结构（20 到 30 秒）
1. 0 到 2.5 秒钩子：一个问题或悬念（“谁先排完？”），大字弹出（ease_out_back）。
2. 主体：可视化对比或过程，同屏显示正在执行的代码行高亮、计时器、步数。
3. 揭晓：暗场 + 大号结论数字（“快了 2.9 倍”）。
4. 结尾 CTA：互动问题 + 下期预告，促评论和关注。
- 底部常驻进度条提升完播率；背景深色网格，配色 GitHub Dark 风格，状态色：比较=黄、交换=红、完成=绿、枢轴=紫。

## 声音
- “Sound of Sorting” 式音效：每次操作一个 45ms 短音，音高随数值变化；两条赛道用不同音色（正弦/方波）。关键节点加和弦提示音。静音播放时画面也要能独立看懂。

## 流程（求快）
1. `--preview` 半分辨率渲染（约 20 秒）并跑 `scripts/qc.py`。
2. 抽帧拼联系表检查。
3. 两个画幅全分辨率渲染，输出到 `/mnt/project-files/videos/<题目>/<题目>_9x16.mp4` 与 `_16x9.mp4`，两条都过 qc。

## 平台要点
- 抖音/快手/视频号/YouTube Shorts/小红书：9:16，前 3 秒决定去留；上下各留约 150px 安全区。
- B站/YouTube 横版：16:9，可延长到 1 到 3 分钟，加讲解节奏。
- 发布永远由用户确认，不代发。

## 选题库
排序对决（归并、堆、基数）、递归可视化、二分查找猜数、寻路 A* vs Dijkstra、蝴蝶效应/混沌、一行代码黑魔法、Bug 找茬、代码打字特效 + 运行结果。
